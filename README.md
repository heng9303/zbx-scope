# ZbxScope

> **One read-only pane for every Zabbix version.**
> 一个只读视图，看遍多个版本的 Zabbix。

**中文别名**：运维视窗 · 面向值班与网络运维的只读数据重呈现层。

> ⚠ **非官方项目**：本项目与 Zabbix LLC 无关联，不替代 Zabbix 官方 UI，
> 不修改任何监控数据。Zabbix 是 Zabbix LLC 的商标。

---

## 它解决什么

Zabbix 官方 UI 功能完整，但值班时"看清当前状态"这件事成本偏高。
ZbxScope 把多个不同版本的 Zabbix 当成**只读数据源**，重做一层更贴合运维阅读习惯的视图：

| 场景 | 官方 UI 的麻烦 | ZbxScope |
|---|---|---|
| 交接班看告警 | 字段多、噪音大 | 按严重度/主机组聚合，一键下钻，14 天趋势 |
| 排查"页面没数据" | 分不清「没数据」和「采集失败」 | 监控项健康模型 + 原始错误文案 + 最近一次数据时间 |
| 对比端口收发 | 一次只能看一条曲线 | 最多 8 条同图、自动收发配对、多单位自动双轴 |
| 看网络拓扑 | 要手画 map，维护成本高 | 自动推断 + Zabbix 映射图 + 人工规划，连线标注置信度 |
| 多套 Zabbix 并存 | 来回切系统、字段还不一样 | 一套视图切实例，版本差异收敛在能力矩阵 |

---

## 特性

- **只读是硬闸门**：服务端 34 个 `*.get` 白名单，写操作根本不会发往 Zabbix，前端被篡改也写不进去；
- **零构建、零依赖**：后端仅 Python 标准库，前端原生 JS + 一份本地 ECharts，`拷目录就能跑`；
- **跨版本实测**：Zabbix **4.0.50 / 7.0.32 / 8.0.0** 三套 API 契约跑通，版本差异只改 `buildCaps()`；
- **诊断而非美化**：采集失败、不支持项、停用项分别标注，区间无数据自动回退"最近数据"并明确提示；
- **响应式**：桌面到 560px 逐级让位，表格卡片内滚动，不撑破页面；
- **可部署**：Docker 非 root + 只读根文件系统 + 审计轮转 + HTTP Basic Auth。

## 5 分钟跑起来

```bash
# 1. 生成配置（配置文件不入库，见下方安全说明）
cp deploy/config.docker.example.json real/config.json
#    填入各实例的 API 地址与只读凭据；本地把 bind 改成 127.0.0.1

# 2. 起服务（无需 pip install / npm install / 构建）
cd real && python3 server.py
# → http://127.0.0.1:8770/
```

Docker 部署、远程环境、访问控制与审计轮转见 [`deploy/README-部署.md`](deploy/README-部署.md)。

## 三层结构

```
浏览器 SPA  ──POST /api_jsonrpc.php──▶  server.py 只读代理  ──▶  Zabbix
（零构建，原生 JS）                    34 方法白名单 + 凭据隔离 + 审计
```

凭据只存在于服务端 `config.json`，浏览器拿不到；所有请求经代理转发并计入审计日志。

## 安全与边界

- **凭据不入库**：`real/config.json`、`audit.jsonl`、运行时抓取数据均在 `.gitignore` 中；
- **不做写操作**：告警确认、维护窗口、任何 `*.update/*.create/*.delete` 都在服务端拒绝；
- **不引入框架/打包器**，不建本地时序库，不替代官方 UI；
- 拓扑连线是**推断 + 人工修正的草图**，持续标注置信度，不等同于物理拓扑；
- 文档中的内网地址已统一替换为语义占位符（`DEPLOY_HOST` / `ZBX4_HOST` 等）；真实地址只存于**不入库**的本地映射表 `docs/.local-addresses.md`（见 `09` 第五节）。
