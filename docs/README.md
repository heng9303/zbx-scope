# Zabbix 运维控制台 · 开发文档

> 一套**只读**的 Zabbix 数据展示层：不替换 Zabbix 主 UI、不修改任何监控数据，
> 面向「大屏/顶屏值班」和「拓扑扫一眼」两个场景。
>
> 最后更新：2026-11-07 · 当前版本 v4.2（P0 安全加固已完成）
> 本轮新增：`08` 产品路线总纲、`deploy/release.sh` 发布快照机制

---

## 5 分钟跑起来

```bash
cd real
python3 server.py          # 只读代理，默认 127.0.0.1:8770
```

打开 <http://127.0.0.1:8770/?profile=zbx7>；
**已部署的远程开发环境**直接访问 `http://DEPLOY_HOST:8770/`（真实地址按不入库的 `docs/.local-addresses.md` 还原，内网直连，无需隧道）。

无需 pip install、无需 npm install、无需构建。凭据在 `real/config.json`。

## 一句话说清三层

```
浏览器 SPA  ──POST /api_jsonrpc.php──▶  只读代理 server.py  ──▶  Zabbix
（零构建）                              34 方法白名单 + 凭据隔离 + 审计
```

只读不是靠自觉，是代理里的一道硬闸门：白名单外的方法**不会发往 Zabbix**。

## 三条必须知道的约定

1. **不判断版本号，只读 `CAPS`**。版本差异集中在 `buildCaps()`。
2. **`history.get` 的 `history` 参数必须等于监控项的 `value_type`**，
   传错不报错、只返回 `[]` —— 这是最容易误判"没数据"的坑。
3. **`problem.get` 没有主机字段**，必须用 `objectid`（= triggerid）反查 `trigger.get`。

## 自检命令

```bash
node --check real/public/js/app.js                                     # 语法
export BASIC_AUTH='<user:password>'                                    # 远程启用了 Basic Auth
node real/tests/ui-smoke.mjs zbx4 http://DEPLOY_HOST:8770            # 断言冒烟（20 项，含只读闸门）
BASE=http://DEPLOY_HOST:8770 node real/tests/responsive.mjs zbx7 10683  # 窄屏五档
BASE=http://DEPLOY_HOST:8770 node real/tests/shots.mjs zbx4 10084        # 整页截图
```

测试脚本已给 Chrome 加 `--no-proxy-server`，本机有企业代理也能直连内网 IP。
本地 `access.mode=off` 时不设 `BASIC_AUTH` 即可。
完整迭代流程见 [07-页面迭代路线图](07-页面迭代路线图.md) 第三节；
访问控制与审计轮转见 `deploy/README-部署.md` 第九节。

### 对外交付 / 交给其他 AI 审核

```bash
bash deploy/release.sh --tag <版本> --note "<本批说明>"
```

产物 `dist/releases/zbx-console-<tag>/`：可运行源码 + 部署文件 + 全部文档（自动脱敏）
+ 逐文件 SHA-256 清单 + 交付说明，并附同名 `.tar.gz`。

⚠ **`handoff/` 与旧的 `dist/*.tar.gz` 都是 v4.1 快照**，不含 P0 加固，
对外一律从 `dist/releases/<tag>` 出包。`baseline/standard` 档需先完成 B0-2
（见 [08](08-产品路线与发展方向.md) 第七节），在此之前脚本会明确拒绝而非产出"假精简版"。

## 边界（不做什么）

- 不做告警确认、维护窗口等**任何写操作**；
- 不替换 Zabbix 主 UI；
- 不引入前端框架/打包器，保持"拷目录就能跑"；
- 不做用户体系与权限，只读账号由 Zabbix 侧控制；
- 拓扑是**草图 + 人工修正**，不承诺等同于物理拓扑。
