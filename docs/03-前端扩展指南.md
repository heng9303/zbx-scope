# 03 · 前端扩展指南

> 面向「要在这套页面上加东西」的人。读完后你应该能独立加一个页面、加一个筛选、加一种图。
> 前置：先读 `01-架构与数据流.md` 的第四节。

---

## 一、三条硬约定

违反这三条的改动，后续会越来越难维护，评审时会被打回：

1. **状态只放 `S`**。不新增全局散变量、不把状态挂到 DOM 上（`dataset` 只用于存 id）。
2. **不判断版本号，只读 `CAPS`**。业务代码里出现 `if (version.startsWith("7")...)` 就是错的位置，
   应该在 `buildCaps()` 里补一个能力位。
3. **所有插入 DOM 的外部字符串必须过 `h()`**。主机名、监控项名、触发器描述、错误信息都来自
   Zabbix，属于不可信输入。

## 二、代码地图

`public/js/app.js` 是单 IIFE，函数按下面的顺序排列。加代码请放在对应区域，不要横插到别的区域里。

| 区域 | 关键函数 | 职责 |
|---|---|---|
| 基础设施 | `rpc` `$` `h` `num` `toast` `buildCaps` | 请求、转义、能力矩阵 |
| 格式化 | `fmtTime` `fmtDur` `fmtBps` `fmtVal` | 时间/带宽/带单位数值 |
| 启动取数 | `boot` `loadCore` `hostGetParams` | 一次装载全站数据 |
| 组装行 | `buildRows` `CAT_RULES` `buildBars` | 原始问题 → 展示行 |
| 渲染总览 | `renderAll` `renderProblems` `renderHosts` | 问题页、主机列表 |
| 主机详情 | `loadHostDetail` `renderHostDetail` `renderHdItems` `probeLastData` `renderHdHealth` | 二级页 |
| 健康模型 | `itemHealth` `HEALTH` `healthLabel` `healthColor` | 采集状态口径 |
| 收发配对 | `pairKeyOf` `buildPeerMap` | 端口 in/out 归一化 |
| 图形页 | `loadItemsPage` `renderGraphList` `renderSelBar` `toggleSel` `addPair` `selectItemChart` | 多选对比 |
| 取数 | `fetchRange` `fetchRecent` `renderEmptyChart` | 区间/最近数据/空态回退 |
| 绘制 | `drawSeries` `renderSeries` | ECharts option 组装、统计、图例 |
| 拓扑页 | `loadTopo` `buildAutoModel` `paintTopo` `bindTopoEvents` `renderTopoPage` | 见 `04-拓扑引擎.md` |
| 抽屉 | `showProblemDrawer` | 问题详情侧滑 |
| 路由 | `applyRoute` `showView` | hash → 页面 |
| 事件绑定 | 文件末尾集中段 | 所有 `onclick`/`oninput` |

## 三、加一个新页面（以「磁盘」为例）

### 1. 结构：`index.html`

在最后一个 `<section class="view">` 后面加一个，`id` 必须是 `view-<name>`：

```html
<section class="view" id="view-disks">
  <div class="card">
    <div class="panel-head"><h3>磁盘使用</h3><span class="meta">item.get</span></div>
    <div id="diskBox"><div class="empty">加载中…</div></div>
  </div>
</section>
```

### 2. 页签：`index.html` 的 `.tabs`

```html
<button class="tab" data-tab="disks">磁盘</button>
```

`data-tab` 与 `view-<name>` 的后缀必须一致，`showView()` 靠它切换。

### 3. 路由：`applyRoute()`

```js
if (name === "disks") { showView("disks"); loadDisks(); return; }
```

### 4. 取数 + 渲染

```js
function loadDisks() {
  var box = $("diskBox");
  box.innerHTML = '<div class="empty">读取监控项…</div>';
  return rpc("item.get", {
    search: { key_: "vfs.fs.size" },
    output: ["itemid","hostid","name","key_","lastvalue","units","value_type","state","error"],
    limit: 2000
  }).then(function (items) {
    // 注意：数值全是字符串，比较前先 Number()
    box.innerHTML = items.length
      ? '<table><thead><tr><th>主机</th><th>名称</th><th>值</th></tr></thead><tbody>' +
        items.map(function (i) {
          return "<tr><td>" + h(hostName(i.hostid)) + "</td><td>" + h(i.name) + "</td><td>"
               + h(fmtVal(i.lastvalue, i.units)) + "</td></tr>";
        }).join("") + "</tbody></table>"
      : '<div class="empty">没有匹配的监控项</div>';
  }).catch(function (e) {
    box.innerHTML = '<div class="empty">取数失败：' + h(e.message) + "</div>";
  });
}
```

### 5. 在 `renderAll()` 里登记（如果需要随刷新重建）

页面若依赖全局数据（而非自己请求），在 `renderAll()` 里调用它的渲染函数；
若自己 `rpc`，就在路由里触发，不要两边都调——会重复请求。

### 6. 验证

```bash
node --check real/public/js/app.js
open "http://127.0.0.1:8770/?profile=zbx8#disks"
node tests/ui-smoke.mjs zbx8      # 确认没有新增 JS 错误
```

## 四、加一个筛选条件

以问题页为例，链路是三段，缺一段就不生效：

```
HTML chip（data-*） → 事件绑定写入 S.filt → 渲染函数里按 S.filt 过滤
```

```html
<button class="chip" data-sev="5">灾难</button>
```

```js
document.querySelectorAll('.chip[data-sev]').forEach(function (c) {
  c.onclick = function () {
    document.querySelectorAll('.chip[data-sev]').forEach(function (x) { x.classList.remove("on"); });
    c.classList.add("on");
    S.filt.sev = c.getAttribute("data-sev");
    renderProblems();
  };
});
```

**约定**：筛选值存字符串（`"all"` 表示不限），渲染函数内部自己 `Number()`，
不要把 DOM 的 `dataset` 当状态读第二遍。

## 五、多监控项对比是怎么工作的

这是本轮的核心能力，也是最容易被改坏的地方，单独说明。

### 5.1 数据结构

```js
S.graph.selItems   // ["140403","140529"]  已选 itemid，顺序即颜色顺序
S.graph.peerMap    // {"140403":"140529"}  收发配对索引（由 buildPeerMap 预计算）
S.graph.curItems   // 当前正在画的 itemid（可能被 8 条上限截断）
```

### 5.2 一次绘制的完整链路

```
renderGraphList()            渲染复选框列表（含健康标签、配对按钮、当前值）
  └ 勾选 → toggleSel(id)     → renderSelBar() 更新 chips
  └ 点 ⇄ → addPair(id)       → 把 peerMap 里的对端一起加入 selItems
  └ 点「对比」→ selectItemChart(selItems)
       ├ item.get(itemids[])  一次多取
       ├ 按传入顺序重排          ← 必须！item.get 不保证顺序，颜色会乱跳
       ├ metas[] 每项带 color / health / units
       └ drawSeries(metas)     → fetchRange → 空则 fetchRecent → renderSeries
```

### 5.3 三条必须守住的不变量

1. **顺序即颜色**：`metas` 必须按 `itemids` 的顺序重排（`selectItemChart` 里那段 `byId` 重排）。
   否则同一组监控项刷新两次颜色就变了。
2. **上限 8 条**：超出时 `toast` 提示并截断，不静默丢弃。
3. **单位不同必须分轴**：`renderSeries` 里按 `units` 分组，出现第二种单位就开右轴，
   并把统计值按单位分别格式化。**不要**用第一条序列的单位格式化全部。

### 5.4 收发配对规则

```js
pairKeyOf(it) // key_ 归一化：net.if.in[ifHCInOctets.10] 与 net.if.out[ifHCOutOctets.10]
              // → IFOCTETS.10.DIR[]，两者相等才会被认为是同一端口的一对
```

归一化覆盖三种命名习惯，不依赖模板固定写法：

| 形态 | 例子 |
|---|---|
| Zabbix 标准网络模板 | `net.if.in[ifHCInOctets.10]` ↔ `net.if.out[ifHCOutOctets.10]` |
| 名称带方向词 | `…：接收` ↔ `…：发送`、`(In)` ↔ `(Out)`、`上行` ↔ `下行` |
| 索引在括号里 | `net.if.in[eth0]` ↔ `net.if.out[eth0]` |

新增设备类型（如光模块 `rx/tx`）时，扩展 `pairKeyOf()` 的替换表即可，不要改调用方。

## 六、健康模型（采集异常）

```js
HEALTH = {
  ok:          { label:"正常",     color:"#1F8A62" },
  unsupported: { label:"采集失败", color:"#C93B3B" },  // state=1
  nodata:      { label:"无当前值", color:"#C98A2B" },  // lastclock=0
  disabled:    { label:"已停用",   color:"#8A99A8" }   // status=1
}
```

判定顺序固定：`disabled → unsupported → nodata → ok`。顺序不能换，
因为一个被停用的项同时可能 `lastclock=0`，先判 `nodata` 会给出错误口径。

**页面上的四层展示**，改动时请保持口径一致：

| 位置 | 展示 |
|---|---|
| 主机详情 KPI | 「采集异常 N」= unsupported + nodata |
| 主机详情横幅 | N 项异常、分类计数、合并后的去重原因、最近一次数据时间、只看异常按钮 |
| 监控项表 | 状态列 + 「最近数据」列（历史时间 → lastclock → `—`） |
| 图形页 | 图例上带异常标签；区间无点时回退最近数据并说明 |

**`probed` 标志**：`S.hd.probed` 表示「最后一条历史的探测已结束」。
横幅的三种状态（查询中 / 查到时间 / 查完无结果）靠它区分。
只按 `lastData` 是否为空判断，会把「查完确实没有历史」永久显示成「查询中…」——这是已修过的 bug。

## 七、图形取数的两种口径

```js
fetchRange(metas, rg)      // 按所选区间取；>24h 自动转 trend.get
fetchRecent(metas, 160)    // 不限时间窗，sortfield=clock DESC limit=N，取"最近数据"
```

回退链：`fetchRange` 为空 → `fetchRecent` → 仍为空 → `renderEmptyChart` 给出可读的空态。
回退发生时**必须**调 `showGraphWarn()` 说明「这是最近数据，不是所选区间」，
否则用户会以为区间查询成功。

## 八、CSS 约定

- 变量在 `:root`：`--bg --card --border --text* --accent --ok --warn --bad --sev0..5`。
  新颜色优先用这些，不要新增十六进制魔法值。
- 分区注释与 JS 模块对齐：变量 / 布局 / 顶栏 / 通用组件 / 问题 / 主机 / 详情 / 图形 / 拓扑 / 抽屉 / 响应式。
- 表格类容器统一加 `table-layout:fixed`，长字段（`key_`、主机名）用 `text-overflow:ellipsis`。
  不加 fixed 时长 `key_` 会把数值列挤成一条线。
- **表格必须放进 `.tw` 滚动容器**（`<div class="tw"><table>…</table></div>`）。
  直接放 `.card` 里时，窄屏下 td 会把 body 撑宽，整页横向滚动；
  而 `position:sticky` 的顶栏只有视口宽，滚动后右侧内容会"穿过"顶栏。
- **不要在 `index.html` 里写内联 `grid-template-columns`**。
  内联样式优先级高于媒体查询，会让窄屏折叠规则完全失效
  （主机详情曾因此在 830px 下仍保留 320px 侧栏，主栏被压到 400px）。

### 8.1 响应式断点

窄屏原则是**逐级让位**，不是整体缩放。断点从大到小：

| 断点 | 让掉什么 | 为什么 |
|---|---|---|
| `≤1240px` | 顶栏"刷新于"时间 | 刷新按钮保留即可，时间可在接口页看 |
| `≤1080px` | 顶栏版本号 pill、页面左右 padding | 版本能力矩阵在 `#api` 页完整可见 |
| `≤980px` | 主机详情侧栏折叠；问题表隐「类别/开始」、主机表隐「显示名/模板」 | 保留能判断严重度与范围的列 |
| `≤760px` | 搜索框独占一行、KPI 两列、图形统计两列、拓扑卡片单列 | 触屏宽度下的最低可用密度 |
| `≤620px` | "只读"徽标、主机详情 `key_` 列 | 只读属性仍可由 `#api` 页确认；`key_` 可回桌面宽度看 |
| `≤430px` | KPI 单列 | 再窄两列会截断数字 |

新增页面时按同一套断点写，别只加一条 `max-width:768px` 的"大杂烩"规则。

**验证方式**：`node tests/responsive.mjs zbx8` 会在 7 档宽度（1440→560）
× 4 个页面（问题/主机/详情/拓扑）上断言四件事：

1. `scrollWidth <= innerWidth`（没有横向溢出）
2. 顶栏底部 ≤ 页签顶部（品牌区换行不会压住导航）
3. 品牌文案单行（高度 ≤ 24px）
4. 没有卡片超出视口

—— 这四条恰好对应"看起来只是有点丑"背后的真实布局故障，比肉眼扫一遍可靠。

## 九、实战踩坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 表格列被挤成一条线 | 未设 `table-layout:fixed`，长 `key_` 撑开 | 见上，加 fixed + 省略号 |
| 拓扑首屏字小到看不清 | 把整图按高度塞进容器（缩放 29%） | 按宽度铺满、`overflow:auto`，允许滚动 |
| SVG 居中留大片空白 | `preserveAspectRatio` 默认居中缩放 | 改 `xMinYMin meet`，并给像素宽高 |
| 手工连线点了没反应 | 只重绘 SVG 没重建 model | 改完数据要调 `renderTopoPage()`，不是 `paintTopo(model)` |
| 图例出现但图是空的 | 数据为空却未走空态分支 | 检查 `fetchRange` 返回值与 `value_type` 是否匹配 |
| 切换 hash 后重复请求 | `hashchange` 与 `boot()` 都触发了加载 | 一个页面只保留一个入口：要么路由触发，要么 `renderAll` 触发 |
| 切回图形页坐标轴错位 | ECharts 在隐藏容器里初始化 | `showView("graphs")` 后 `chart.resize()`（已有 80ms 延时） |
| 顶栏文字竖排、压住页签 | 品牌区没 `nowrap`，flex 收缩时逐字换行，把 56px 顶栏撑破 | `.bt/.bs` 加 `white-space:nowrap` + 省略号，`.brand{flex:0 0 auto}` |
| 窄屏右侧内容"穿过"顶栏 | 表格撑破 body 导致整页横向滚动，sticky 顶栏只有视口宽 | 表格进 `.tw` 滚动容器；别让 body 出现横向滚动 |
| 窄屏两栏折不开 | `index.html` 写了内联 `grid-template-columns:…`，压过媒体查询 | 内联样式改成 class（如 `.split.hd`），在媒体查询里覆盖 |

## 十一、统一错误态（P0-3）

新增 `<div id="globalErr" class="gerr" hidden>`（在 `<main>` 顶部）与三个函数：

```js
showGlobalError(title, detail, method)  // 展示卡片：实例/版本/失败方法/原因 + 重新加载/关闭
clearGlobalError()                     // 正常加载后收起
noteRpcFailure(method, e)              // 记录最近一次失败；e.auth 时立即展示认证失效提示
```

约定：

- **只有两处会展示**：`boot()` 的 catch（启动链失败）与运行时 401。
  单个非关键请求失败只记 `S.netErr`，不弹全局卡片，避免正常使用被打扰。
- `rpc()` 统一把 HTTP 401 / 非 2xx / 网络异常转成可读 `Error`，401 打 `e.auth=true`；
  `CHAIN` 的成功/失败记录集中在 `.then/.catch`，不会出现重复条目。
- `/api/meta` 的 fetch 也要单独判断 401，否则会解析到 401 的 HTML 而报 JSON 错误。
- 新增视图时**不要**自己写全屏错误覆盖层，复用这三个函数；切实例会重新 `boot()`，
  成功后自动清除，无需手动处理。
- 冒烟脚本有断言「全局错误条在数据正常时保持隐藏」，改动这块务必跑一次。
