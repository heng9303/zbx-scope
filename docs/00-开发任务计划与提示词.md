## 二、本轮需求与实测结论

### R1 7.0 环境里 11.28 的 485 温湿度传感器没有数据

> **后续更新（v4.1）**：7.0 侧的采集已修复。该主机现在有 2 个监控项
> `11.30-温度_Modbus`（22.7 °C）/ `11.30-湿度_Modbus`（48.8 %），`state=0`、逐分钟上报，
> 页面"采集异常"横幅自动消失（`hdBad=0`），双向对比图双轴正常。
> 下面记录的是修复前的实测，作为"页面看起来没数据"的判型样本保留。

**实测结果（重要，与描述有偏差）：**

| 环境 | 主机 | 事实 |
|---|---|---|
| 7.0 `10.51.26.103` | `10.51.11.28`（hostid 10683） | 当时**只有主机记录，0 个监控项、0 个接口、0 个模板**，分组 `Discovered hosts`。不是页面漏取，是这个主机确实没有数据 |
| 8.0 `10.51.26.102` | `10.51.11.28`（hostid 10925） | 6 个监控项：11.28 温度/湿度 Modbus、11.29 温度/湿度、11.30 温度/湿度 |

8.0 上 11.28 的真实状态：

```
141275  11.28-温度_Modbus  modbus.get[tcp://10.51.11.28:502,1,3,512,...]  state=1（不支持）lastclock=0
141281  11.28-湿度_Modbus  modbus.get[tcp://10.51.11.28:502,1,3,513,...]  state=1（不支持）lastclock=0
error: Timeout occurred while gathering data.
history 最后一条：2026-10-13 07:16:35，值 23.8
```

对比 11.30：`lastclock=2026-10-27 23:16:33`，值 22.8，正常。

**根因不是前端过滤，而是三层叠加：**
1. 设备 10-13 起 Modbus 采集超时，监控项进入 `state=1`，Zabbix 不再更新 `lastvalue/lastclock`；
2. Zabbix 前端「最新数据/图形」仍能查到**历史**，所以你在 Zabbix 里看到"有数据"；
3. 我们的图形页默认 24h 区间，而历史只到 10-13，查询结果为空 → 页面显示"没有数据"，且没有解释。

**修复方向（不改 Zabbix 数据）：**
- 增加监控项健康模型：`正常 / 采集失败(state=1) / 无当前值 / 已停用`；
- 主机详情显示采集异常汇总、错误原因、最近一次数据时间；
- 图形页区间无点时，自动回退查询"最近 N 个点"，画出并明确标注"最近数据，非所选区间"；
- 保留原始错误文案，不美化、不隐藏。

### R2 图形里端口发送/接收分开，希望同时选多个监控项

**现状**：`item.get` 已返回该主机全部数值项（8.0 单交换机 619 项），但一次只能画 1 项。
**方案**：
- 监控项列表加复选框，最多同时 8 条序列；
- 「收发配对」按 `net.if.in[ifHCInOctets.<idx>]` ↔ `net.if.out[ifHCOutOctets.<idx>]` 的索引配对，兼容 `(In/Out)`、`发送/接收`、`上行/下行` 命名；
- 已选序列以 chips 展示，可单独移除；
- 深链 `#items/<id1>,<id2>`，可分享"某端口收发对比"视图；
- 不同单位/量级时自动双 Y 轴，超过 8 条提示而非静默截断。

### R3 Zabbix 4.0 接入

```
API   http://10.51.31.201/zabbix/api_jsonrpc.php
UI    http://10.51.31.201/zabbix/index.php
版本  4.0.50（apiinfo.version 实测）
认证  test / <PASSWORD> → user.login（会话 600s，失效自动重登）
```

**实测**：API 可达；`user.login` 成功后 157 台主机、112 条在警问题、56 个原生图形。
最初用 `Admin` 登录会返回
`Incorrect user name or password or account is temporarily blocked.`——
这句把「密码错」和「账号被锁」合并成一条，只能靠等 30 秒锁定窗口后复测来区分，
所以**优先核对用户名**，别急着反复重试（会真的把账号锁住）。

**4.0 适配点**：`selectGroups → groups`（不是 `hostgroups`）、`map.selements[].elementid`、
无 `active_available`、`problem.get` 不支持 `hostids`（走 trigger 反查）、
`auth` 必须放在 JSON-RPC 请求根级、`user.get` 的用户名字段是 `alias`。

### R4 拓扑扩展

接受"独立于 Zabbix、基于已取数据做连线规划"。方案：
- 三种模式：**真实映射图**（map.get）/ **自动拓扑**（数据推断）/ **规划编辑**；
- 自动布局：按主机组聚类，组内星型/网格；
- 连线来源与置信度：`map` 100% → `lldp/cdp` 90% → 同 /24 网段 60% → 手工规划 100%；
- 规划模式：拖拽、连线、删线、导出/导入 JSON、本地持久化；
- 节点颜色继续绑定真实 `problem.get`，链路告警按端点最高级别推导并标注"推断"。

### R5 自我验证审核与修复
`node --check` + headless Chrome 逐页截图 + `jsErr` 检测 + 只读闸门回归 + 三版本冒烟。

### R6 开发文档
`docs/` 七篇：计划与提示词、架构、API 契约、前端指南、拓扑引擎、部署运维、变更日志。

## 三、任务分解（可直接作为子任务提示词）

### T1 数据健康模型与无数据回退
**改动**：`public/js/app.js`（`itemHealth`、`renderHdItems`、`renderHostDetail`、`drawSeries`）
**验收**：
- 8.0 `#/host/10925` 显示"4 个监控项采集失败"，错误文案可见，最近数据时间 2026-10-13 07:16；
- `#/item/141275` 默认 24h 无点，自动回退并画出 10-13 的曲线，横幅说明"最近数据"；
- 11.30 的项正常显示当前值，不误报。

**提示词**：
> 在现有 SPA 中新增 item 健康模型：根据 `status/state/lastclock/error` 计算 normal/unsupported/nodata/disabled。
> 主机详情增加采集异常汇总条与"只看异常"筛选；对 state=1 的项（最多 10 个）查询 history/trend 最后一条，
> 展示最近数据时间。图形绘制在所选区间 0 点时，回退查询最近 120 个点并绘制，明确标注非所选区间。
> 不得修改 Zabbix 数据，不得隐藏原始错误。

### T2 监控项多选与收发配对
**改动**：`app.js`（`renderGraphList`、`selectItemChart`、新增 `peerOf`/`toggleItem`）
**验收**：勾选 2 项后点"对比"出双线；对 `net.if.in[...]` 点"配对"自动带上 out；深链 `#items/a,b` 可复现；>8 项给出提示。

### T3 Zabbix 4.0 接入

会话过期自动重登一次；前端主机组正常显示。**已通过**。

### T4 拓扑引擎

### T5 前端拆分

**验收**：拆分后功能与拆分前一致；`node --check` 通过；页面无 404。

### T6 自检
**验收**：三版本关键页截图无空白/重叠/报错；代理白名单拦截写操作仍生效。
