# 05 · 部署与运维

> 目标：换一台机器，10 分钟内能跑起来；出问题时知道先看哪里。

---

## 一、环境要求

| 项 | 要求 |
|---|---|
| Python | 3.8+，**仅标准库**，无需 pip install |
| 浏览器 | Chrome / Edge / Safari 近两年版本（用到 `fetch`、`Promise`、`PointerEvent`） |
| Node | 18+，**仅测试脚本用**（`tests/*.mjs`），运行时不依赖 |
| 网络 | 代理需能访问 Zabbix 的 `api_jsonrpc.php`；浏览器只需访问代理 |

不需要 Nginx、不需要数据库、不需要构建步骤。

---

## 二、启动

```bash
cd real
python3 server.py
# 只读代理已启动  http://127.0.0.1:8770/
```

访问 `http://127.0.0.1:8770/?profile=zbx8`。

**环境变量**（覆盖配置，便于多实例共存）：

```bash
ZBX_PORT=8771 ZBX_BIND=0.0.0.0 python3 server.py
```

> 默认绑定 `127.0.0.1`。改成 `0.0.0.0` 前请先读本文第六节。

## 三、配置 `config.json`

### 3.1 结构

```json
{
  "active": "zbx8",
  "bind": "127.0.0.1",
  "port": 8770,
  "timeout": 60,
  "profiles": [
    {
      "id": "zbx8",
      "label": "生产 8.0",
      "upstream": "http://ZBX8_HOST/api_jsonrpc.php",
      "auth": "token",
      "token": "…"
    },
    {
      "id": "zbx4",
      "label": "测试 4.0",
      "upstream": "http://ZBX4_HOST/zabbix/api_jsonrpc.php",
      "auth": "login",
      "user": "test",
      "password": "…",
      "timeout": 30
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `active` | 未指定 `?profile=` 时的默认实例 |
| `auth` | `token`（5.0+）或 `login`（4.0–6.x） |
| `upstream` | 必须指向 `/api_jsonrpc.php`，**不是** Web 首页 |
| `timeout` | 单次上游请求超时（秒）。跨公网链路建议 30–60 |

改完配置**必须重启**进程（配置在启动时读取）。

### 3.2 安全建议

- `config.json` 里有明文 Token/密码，**权限设 600**，不要进 Git；
- 在 Zabbix 侧为本系统单独建一个**只读用户 + 只读角色**，不要复用 Admin；
- 4.0 的 `login` 模式会在进程内存里缓存 `sessionid`（600 秒），
  该账号的失败登录计数与你在浏览器登录共用，排查时注意别把账号锁了。

## 四、Zabbix 侧准备（只读账号）

8.0 示例（UI 操作，不改监控数据）：

1. `用户 → 用户角色`：新建角色，`监控数据` 只勾**读取**，`API` 只勾读取类方法，**不勾**任何 `编辑/创建/删除`；
2. `用户 → 用户`：新建用户，挂上该角色，所属用户组给 `Monitoring` 读权限；
3. `用户 → API 令牌`：为该用户创建 Token（8.0 支持按角色限制），把 Token 填进 `config.json`。

4.0 没有 Token，只能用账号密码 `login`；角色体系也不存在，靠用户类型（User）限制。
**务必不要用 Super Admin**。

## 五、对外发布（可选）

代理本身可以直接当静态服务器用，也可以放到 Nginx 后面：

```nginx
location /zbx-console/ {
    proxy_pass http://127.0.0.1:8770/;
    proxy_set_header Host $host;
    proxy_read_timeout 90s;
}
```

注意两点：

1. **必须自建鉴权**。代理没有任何登录机制，挂到内网可见的位置等于把 Zabbix 只读数据公开。
   建议加 SSO / IP 白名单 / `auth_basic` 至少一层。
2. 路径带前缀时，`app.js` 里的 `API = "/api_jsonrpc.php"` 是绝对路径，会 404。
   要么把代理挂在根路径，要么改 `API` 常量并同步 `index.html` 里的 `css/js` 引用。

## 六、安全边界（务必理解）

| 保证 | 实现 | 边界 |
|---|---|---|
| 不修改 Zabbix 数据 | 34 个方法白名单，其余在本地拒绝 | 只要有人能改 `server.py` 就能加白名单，所以**文件权限也要管** |
| 凭据不下发浏览器 | 凭据只在 `server.py` 进程内 | 能读到 `config.json` 的人就能拿到 |
| 只绑本机 | 默认 `127.0.0.1` | 改 `0.0.0.0` 后此保证失效 |
| 可审计 | `audit.jsonl` 追加写 | 只记转发与拦截，不记页面点击 |

**这不是一个多租户系统**，也没有用户体系。它的前提是：
部署在受控网络内、使用者可信、Zabbix 侧用只读账号兜底。

## 七、排障清单

按「现象 → 先看哪 → 常见原因」组织，覆盖实际遇到过的问题。

### 7.1 页面打不开 / 空白

| 检查 | 命令 |
|---|---|
| 进程在不在 | `lsof -ti tcp:8770` |
| 静态文件对不对 | `curl -sI http://127.0.0.1:8770/` 应返回 200 |
| 有没有 404 | 浏览器 Network 面板看 `css/app.css`、`js/app.js`、`vendor/echarts.min.js` |

### 7.2 顶栏显示"连接失败"

```bash
curl -s http://127.0.0.1:8770/api/meta | head -c 400
curl -s -X POST http://127.0.0.1:8770/api_jsonrpc.php \
  -H 'Content-Type: application/json-rpc' \
  -d '{"jsonrpc":"2.0","method":"apiinfo.version","params":{},"id":1}'
```

- `apiinfo.version` 返回版本号 → 网络通，问题在认证或参数；
- 返回 `Proxy error` → 看 `data` 字段的上游原文。

### 7.3 认证类错误

| 上游原文 | 原因 | 处理 |
|---|---|---|
| `Incorrect user name or password or account is temporarily blocked.` | 密码错，或已因连续失败被锁 30 秒 | 先在浏览器确认能登录；等 30 秒再试；**不要连续重试** |
| `Invalid parameter "/": unexpected parameter "username".` | 上游是 4.0/5.2 以下，却用了 `username` | 已由 `_login()` 按版本自动处理；若出现说明版本探测失败 |
| `Session terminated, re-login, please.` | 会话过期 | 代理会自动重登一次；反复出现说明两次请求间隔 > 600 秒 |
| `Not authorized` / 空结果 | Token 权限不足或角色没给读权限 | 在 Zabbix 侧确认角色 |

### 7.4 有主机但没数据

这类"看起来没数据"分三种，**必须先分清**：

| 情况 | 特征 | 判断方法 |
|---|---|---|
| 主机没有监控项 | 详情页监控项 0 | `item.get(hostids=[id])` 返回 `[]`，且该主机 0 接口 0 模板 |
| 监控项采集失败但有历史 | `state=1`、`lastclock=0`、有 `error` | 详情页出现"采集异常"横幅；`history.get` 能查到旧点 |
| 区间超出历史 | 区间内 0 点 | 图形页会自动回退"最近数据"并横幅说明 |
| **连主机都看不到** | 主机列表 0 行，但 `problem.get` / `event.get` 有数 | 账号权限问题：`host.get(countOutput:true)` 返回 `"0"`，同时 `event.get` 有几千条 → 用户组没给主机组读权限 |

第四种在 4.0 上很常见：账号能登录、`action.get`/`event.get` 有数，
但 `host.get` / `hostgroup.get` / `item.get` 全是空。此时**不是代码问题**，
去 Zabbix 的 `用户 → 用户组 → 权限` 给该组勾上一个主机组的「读」即可。

第三种是本系统主动处理过的场景，看到"最近数据（非所选区间）"横幅属**正常提示**，不是故障。

### 7.5 图形空白

1. 看 `#api` 页的调用日志，`history.get` 的 `count` 是不是 0；
2. 0 → 检查该监控项 `value_type` 与请求的 `history` 参数是否一致（见 `02` 文档第五节）；
3. 非 0 但没画出来 → 看浏览器 Console 是否有 ECharts 报错、容器高度是否为 0。

### 7.6 写操作被拦（这是**预期行为**）

```
Blocked by read-only proxy
```

说明闸门工作正常。若确实需要某个读方法，把它加进 `server.py` 的 `READ_ONLY` 集合并重启；
**不要**为了绕过闸门去改前端。

### 7.7 端口被占

```bash
lsof -ti tcp:8770 | xargs kill
```

## 八、日常运维

| 事项 | 做法 |
|---|---|
| 看谁在调什么 | `#api` 页的"本次会话的真实调用日志"，或 `tail -f audit.jsonl` |
| 审计归档 | `audit.jsonl` 只追加，按月切割：`mv audit.jsonl audit-$(date +%Y%m).jsonl` |
| 前端缓存 | 静态文件带 `Cache-Control: no-store`，改完刷新即可，不用清缓存 |
| 升级 | 覆盖 `public/` 与 `server.py` 后重启；`config.json` 保留 |
| 回滚 | 保留 `index.v3.html.bak` 之类快照，整文件替换即可（无构建产物） |

## 九、当前部署状态（截至本版）

| 实例 | 地址 | 版本 | 认证 | 状态 |
|---|---|---|---|---|
| `zbx8` | `http://ZBX8_HOST/api_jsonrpc.php` | 8.0.0 | Token | ✅ 正常，冒烟 27 项全过 |
| `zbx7` | `http://ZBX7_HOST/api_jsonrpc.php` | 7.0.31 | Token | ✅ 正常，冒烟 19 项全过；`11.28` 温湿度已恢复采集 |
| `zbx4` | `http://ZBX4_HOST/zabbix/api_jsonrpc.php` | 4.0.50 | login（`test`） | ✅ 已打通：157 台主机 / 112 条在警问题，主机详情、图形、拓扑均正常，冒烟 19 项全过 |

`zbx4` 曾经的两个坑，都已修在代码里，换环境时不用再踩：

1. **账号用 `test`，不是 `Admin`**。4.0 的 `Admin` 密码与此处不同，用错会得到
   `Incorrect user name or password or account is temporarily blocked.`——这句话把
   「密码错」和「被锁」合并成一条，**只能靠等 30 秒锁定窗口后复测来区分**。
2. **`auth` 必须放在 JSON-RPC 请求对象的根级**，不能塞进 `params`。
   塞进 `params` 时 4.0 会回 `{"code":-32602,"data":"Not authorised."}`，
   而登录本身是成功的，很容易误判成「账号没权限」。见 `02` 文档坑 #10。
3. 该账号挂在 `Zabbix administrators` 组但用户类型是 **User**（type=1），
   主机可见性完全由用户组的**主机组权限**决定。刚建号时 `rights` 为空，
   `host.get` 会静默返回 `[]`（`countOutput` 也是 `"0"`），但 `event.get` 仍有数据——
   这种「事件有、主机没有」的组合就是权限未授权的特征。

## 十、访问控制与审计轮转（v4.2）

远程部署绑 `0.0.0.0` 后必须启用认证 —— 页面无任何内置鉴权，端口可达即数据可达。

`config.json` 新增两段（完整说明见 `deploy/README-部署.md` 第九节）：

```jsonc
"access": {
  "mode": "basic",              // off = 免认证（仅本地开发）
  "user": "zbxview",
  "password": "<随机口令>",
  "public_paths": ["/api/ping"] // 健康检查必须免认证
},
"audit_rotate": { "max_bytes": 5242880, "max_files": 5 }
```

- 认证在 `server.py` 内实现，零依赖、无额外容器；凭据只在服务端，不下发浏览器。
- **改 `access` 不需要重建镜像**：`config.json` 是运行时只读挂载，`docker compose restart` 即可。
- 想临时关闭认证：把 `mode` 改成 `off` 再 restart；恢复改回 `basic`。
- 审计超过 `max_bytes` 自动滚成 `audit.jsonl.1/.2/...`，最多保留 `max_files` 份；
  轮转与追加在同一把线程锁内完成，不会互相踩。
- 排障：容器日志启动时会打印 `访问控制 basic（免认证路径 ['/api/ping']）` 与
  `审计轮转 5 MB × 5 份`，改配置后先看这两行确认是否生效。
- `/api/meta` 会返回 `access_mode` 与 `audit_rotate`，方便远程核对配置（不含凭据）。
